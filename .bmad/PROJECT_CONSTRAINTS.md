# 项目约束 - BMAD-EVO 框架

> 本文件定义了 BMAD-EVO 框架开发和演进过程中必须遵守的约束。
> 所有 Agent 在参与本项目时，必须严格遵循以下约束。

---

## 技术栈约束

### 运行时环境
- **Node.js**: >= 18.0.0
- **包管理器**: npm / pnpm
- **部署目标**: OpenClaw Gateway (Linux x64)

### 依赖管理
- 禁止引入重量级依赖（>1MB）
- 优先使用 OpenClaw 内置工具
- 外部依赖必须记录在 `package.json` 中
- 禁止使用已废弃或有严重安全漏洞的包

---

## 架构约束

### 目录结构
```
bmad-evo/
├── .bmad/                    # BMAD 工作目录
│   ├── checkpoints/          # 阶段检查点
│   ├── decisions/            # 决策记录 (ADRs)
│   ├── logs/                 # 执行日志
│   └── PROJECT_CONSTRAINTS.md # 本文件
├── agents/                   # Agent 角色定义
├── lib/                      # 核心库代码
├── templates/                # 模板文件
├── scripts/                  # 辅助脚本
└── SKILL.md                  # Skill 描述文件
```

### 模块化原则
- 每个 Agent 角色独立实现（Planner/Scheduler/Worker）
- 核心逻辑与 OpenClaw 工具层分离
- 配置与代码分离

### 接口约束
- 所有 Agent 必须通过标准输入/输出通信
- 禁止直接访问主会话的私有数据
- 文件系统访问限制在 `/root/.openclaw/workspace/` 内

---

## 代码风格约束

### 命名规范
- **文件**: kebab-case (如 `project-loader.sh`)
- **函数**: camelCase (如 `loadProject()`)
- **常量**: UPPER_SNAKE_CASE (如 `MAX_RETRY_COUNT`)
- **类**: PascalCase (如 `ConstraintChecker`)

### 注释要求
- 所有公开函数必须有 JSDoc 注释
- 复杂算法必须包含实现思路说明
- 约束违反必须记录到 `.bmad/decisions/` 目录

### 代码质量
- 禁止硬编码路径（使用环境变量）
- 禁止静默捕获异常（必须记录或抛出）
- 所有外部命令调用必须验证返回值

---

## 安全约束

### 数据安全
- 禁止记录敏感信息（API Keys、密码等）到日志
- 用户文件访问前必须确认路径在 workspace 内
- Git 推送前必须执行安全检查（git-safety-guardian）

### 执行安全
- 禁止执行未经验证的外部脚本
- 所有 `exec` 调用必须有超时限制（默认 30s）
- 禁止使用 `eval` 执行用户输入

### 权限控制
- 只读操作不需要确认
- 写入操作需要用户确认（除非在 cron 中明确授权）
- 删除操作必须使用 `trash` 而非 `rm`

---

## 交付约束

### 文档要求
- 每个阶段必须生成 `PHASE{N}_REPORT.md`
- 重大决策必须记录 ADR（架构决策记录）
- 约束违反必须有自反思记录和解决方案

### 测试要求
- 核心功能必须有测试脚本
- 回归测试必须覆盖所有历史问题
- 性能关键路径必须有基准测试

### 版本管理
- 遵循语义化版本（SemVer）
- 每个版本必须有变更日志
- 破坏性变更必须在 `SKILL.md` 中明确标注

---

## 约束检查

### 自动检查点
1. **阶段开始前**: 加载并验证约束文件存在
2. **阶段结束后**: 检查是否有约束违反
3. **Git 提交前**: 预提交钩子检查约束合规性

### 违反处理流程
```
检测到约束违反
    ↓
记录到 .bmad/decisions/VIOLATION-{timestamp}.md
    ↓
自反思：分析原因和影响
    ↓
提出解决方案
    ↓
用户确认或自动修复
    ↓
更新约束或修复代码
```

---

## 约束演进

本约束文件本身可以演进，但必须遵循以下流程：

1. 提出约束修改建议（记录到 `.bmad/decisions/`）
2. 评估修改影响范围
3. 用户确认
4. 更新 `PROJECT_CONSTRAINTS.md`
5. 记录版本号变更

## 快速参考

### 🚫 禁止事项
- 直接修改 OpenClaw 核心配置
- 绕过约束检查
- 在未确认的情况下删除用户文件
- 记录敏感信息到日志或 Git

### ✅ 推荐做法
- 使用 `cron_manager.py` 管理定时任务
- 使用 `git-safety-guardian` 检查推送
- 所有决策记录到 `.bmad/decisions/`
- 阶段报告使用标准模板

### ⚠️ 注意事项
- 约束文件必须存在才能启动 BMAD-EVO 项目
- 约束违反会自动触发自反思流程
- 定期回顾和更新约束（建议每月一次）
